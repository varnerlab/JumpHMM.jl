JumpHMM.MyJumpHiddenMarkovModel — Type
mutable struct MyJumpHiddenMarkovModel <: AbstractMarkovModel

The MyJumpHiddenMarkovModel mutable struct holds a hidden Markov model of the growth rates of one asset. The states partition the growth rates, each state emits growth rates from a Student-t distribution, and a jump episode can move the asset into the tails.

Required fields

  • number_of_states::Int64: The number of states of the model
  • laplace_μ::Float64: The location of the Laplace distribution that sets the state boundaries
  • laplace_b::Float64: The scale of the Laplace distribution that sets the state boundaries
  • boundaries::Array{Float64,1}: The number_of_states + 1 edges of the states. The first edge is -Inf and the last edge is Inf
  • transition::Array{Float64,2}: The transition matrix. Row i holds the probabilities of moving from state i to each state
  • stationary::Array{Float64,1}: The stationary distribution of the transition matrix
  • emission_μ::Array{Float64,1}: The location of the Student-t emission distribution of each state
  • emission_σ::Array{Float64,1}: The scale of the Student-t emission distribution of each state
  • emission_n::Array{Int64,1}: The number of observations used to estimate the emission of each state
  • emission_fallback::Array{Bool,1}: A flag that is true if a state uses the standard deviation of all growth rates, because the state had fewer than min_obs growth rates or a standard deviation below 1e-12
  • ν::Float64: The degrees of freedom of the Student-t emission distributions
  • ϵ::Float64: The probability that a jump episode starts on a given day. A value of 0.0 means the model has no jumps
  • λ::Float64: The mean of the Poisson episode length, in trading days
  • p_neg::Float64: The probability that a day of a jump episode is in the negative tail
  • N_tail::Int64: The number of states in each tail that a jump episode can reach
  • Δt::Float64: The time step of the growth rates, in years

JumpHMM.build — Method
build(model::Type{MyJumpHiddenMarkovModel}, data::NamedTuple) -> MyJumpHiddenMarkovModel

Estimate a hidden Markov model of the growth rates of one asset. We cut the growth rates into states, count the moves between states, estimate the emission distribution of each state, and solve for the stationary distribution.

Arguments

  • model::Type{MyJumpHiddenMarkovModel}: The type to build
  • data::NamedTuple: The inputs. The required keys are:
    • growth_rates::Array{Float64,1}: The growth rates, at least two finite values that are not all equal
    • number_of_states::Int64: The number of states, at least 1
    • ν::Float64: The degrees of freedom of the Student-t emission distributions, above 0

Returns

  • MyJumpHiddenMarkovModel: The estimated model

Optional Arguments

The optional keys of data and their defaults are:

  • ϵ::Float64: The probability that a jump episode starts on a given day, between 0 and 1. A value of 0.0 means no jumps. Default: 0.0
  • λ::Float64: The mean of the Poisson episode length, in trading days, above 0. Default: 1.0
  • p_neg::Float64: The probability that a day of a jump episode is in the negative tail, between 0 and 1. Default: 0.52
  • N_tail::Int64: The number of states in each tail that a jump episode can reach, at least 1. Default: 5
  • Δt::Float64: The time step of the growth rates, in years. Default: 1/252
  • min_obs::Int64: The fewest growth rates a state needs to use its own emission estimates. Default: 2

Any other key throws an ArgumentError. Each key must have the type shown. For example, write ν = 5.0, not ν = 5.

Example

model = JumpHMM.build(JumpHMM.MyJumpHiddenMarkovModel, (
    growth_rates = growth_rates,
    number_of_states = 100,
    ν = 5.0
));

JumpHMM.simulate — Method
simulate(model::MyJumpHiddenMarkovModel, number_of_steps::Int64; number_of_paths::Int64 = 1000,
    start::Union{Int64,Nothing} = nothing, seed::Union{Int64,Nothing} = nothing) -> NamedTuple

Simulate synthetic growth rate paths from a jump hidden Markov model. Day 1 of each path starts in a state and emits a growth rate. Every later day is an ordinary day or a day of a jump episode. On an ordinary day, the model draws the next state from the transition matrix. On a day of a jump episode, the model draws one of the tail states. A jump episode starts with probability ϵ on a given day and lasts a Poisson(λ) number of days. An episode length of zero makes the day an ordinary day. An episode that would run past the last day stops at the last day.

Arguments

  • model::MyJumpHiddenMarkovModel: The model to simulate from
  • number_of_steps::Int64: The number of days in each path. Must be at least 1

Returns

  • NamedTuple: Three matrices with one row for each day and one column for each path.
    • growth_rates::Array{Float64,2}: The simulated growth rates
    • states::Array{Int64,2}: The state on each day
    • episodes::Array{Bool,2}: A flag that is true if the day is part of a jump episode

Optional Arguments

  • number_of_paths::Int64: The number of paths to simulate, at least 1. Default: 1000
  • start::Union{Int64,Nothing}: The state of day 1, from 1 to number_of_states. If nothing, the start state is drawn from the stationary distribution. Default: nothing
  • seed::Union{Int64,Nothing}: The seed of the global random number generator. If nothing, the generator is not reseeded. Default: nothing

Example

model = JumpHMM.build(JumpHMM.MyJumpHiddenMarkovModel, (growth_rates = G, number_of_states = 100, ν = 5.0, ϵ = 1e-3, λ = 90.0));
paths = JumpHMM.simulate(model, 252; number_of_paths = 100, seed = 5660);

JumpHMM.tune — Method
tune(model::MyJumpHiddenMarkovModel, growth_rates::Array{Float64,1}; ϵ_range = range(1e-4, 2.5e-2, length = 20),
    λ_range = range(10.0, 160.0, length = 16), number_of_paths::Int64 = 200, number_of_steps::Int64 = 0,
    w_κ::Float64 = 0.20, p_neg::Float64 = model.p_neg, N_tail::Int64 = model.N_tail, acf_lags::Int64 = 25,
    seed::Union{Int64,Nothing} = nothing) -> MyJumpHiddenMarkovModel

Search a grid of jump settings (ϵ, λ) for the pair whose simulated paths best match the data. For each pair, we simulate paths and compare them with the data on two things: the autocorrelation of the absolute growth rates, and the excess kurtosis of the growth rates. The tuned model gets the pair with the lowest mean score. The input model is not changed. If no pair produces a path with a jump episode, we warn and return the first pair of the grid. Before any simulation, we check that every candidate value and the tail settings are valid jump settings.

Arguments

  • model::MyJumpHiddenMarkovModel: The model to tune. We copy it, and we do not change it
  • growth_rates::Array{Float64,1}: The growth rates of the data, for example from excess_growth_rates

Returns

  • MyJumpHiddenMarkovModel: A copy of model with the best ϵ and λ, and with p_neg and N_tail set to the arguments

Optional Arguments

  • ϵ_range: The candidate values of ϵ, the probability that a jump episode starts on a given day. Each value is between 0 and 1. Default: range(1e-4, 2.5e-2, length = 20)
  • λ_range: The candidate values of λ, the mean of the Poisson episode length, in trading days. Each value is above 0. Default: range(10.0, 160.0, length = 16)
  • number_of_paths::Int64: The number of paths to simulate for each pair, at least 1. Default: 200
  • number_of_steps::Int64: The number of days in each path. If 0, we use the number of days in growth_rates. Default: 0
  • w_κ::Float64: The weight of the kurtosis error in the score. Default: 0.20
  • p_neg::Float64: The probability that a day of a jump episode is in the negative tail, between 0 and 1. Default: model.p_neg
  • N_tail::Int64: The number of states in each tail that a jump episode can reach, at least 1. Default: model.N_tail
  • acf_lags::Int64: The number of lags of the autocorrelation. We shorten it if the paths or the data are too short. Default: 25
  • seed::Union{Int64,Nothing}: The seed of the global random number generator. If nothing, the generator is not reseeded. Default: nothing

Example

model = JumpHMM.build(JumpHMM.MyJumpHiddenMarkovModel, (growth_rates = G, number_of_states = 100, ν = 5.0));
tuned = JumpHMM.tune(model, G; ϵ_range = range(1e-4, 5e-3, length = 3), λ_range = range(10.0, 160.0, length = 3),
    number_of_paths = 20, seed = 5660);

JumpHMM.validate — Method
validate(model::MyJumpHiddenMarkovModel, growth_rates::Array{Float64,1}; number_of_paths::Int64 = 1000, α::Float64 = 0.05,
    acf_lags::Int64 = 25, seed::Union{Int64,Nothing} = nothing) -> MyValidationReportModel

Simulate paths from the model and compare each path with the data. For each path, we compute the Kolmogorov-Smirnov and Anderson-Darling p-values, the Wasserstein and Hellinger distances, the mean absolute error in the autocorrelation of the absolute growth rates, and the excess kurtosis. Each path has as many days as growth_rates.

  • growth_rates::Array{Float64,1}: The growth rates of the data, for example from excess_growth_rates

Returns

  • MyValidationReportModel: The results for each path, and their summaries over the paths

Optional Arguments

  • number_of_paths::Int64: The number of paths to simulate, at least 1. Default: 1000
  • α::Float64: The significance level of the tests. A path passes a test if its p-value is above α. Default: 0.05

  • seed::Union{Int64,Nothing}: The seed of the global random number generator. If nothing, the generator is not reseeded. Default: nothing

JumpHMM.hellinger_distance — Function
hellinger_distance(x::Array{Float64,1}, y::Array{Float64,1}) -> Float64

Compute the Hellinger distance between two samples. We split the range from the smallest to the largest value of both samples into equal-width bins, count the values of each sample in each bin, and scale each count to a probability. Every value is counted: a value v falls in bin floor((v - lo) / (hi - lo) * number_of_bins) + 1, where lo and hi are the smallest and largest values, and the largest value falls in the last bin. The number of bins is the larger of 30 and the square root of the size of the larger sample. If both samples hold only the same single value, the distance is 0.0.

Arguments

  • x::Array{Float64,1}: The first sample, with at least one value
  • y::Array{Float64,1}: The second sample, with at least one value

Returns

  • Float64: The Hellinger distance between x and y, from 0.0 for the same bin probabilities to 1.0 for samples with no bin in common

Example

d = JumpHMM.hellinger_distance([0.1, -0.2, 0.3], [0.0, 0.2, 0.4]);

JumpHMM.simulate — Method
simulate(portfolio::MyPortfolioModel, number_of_steps::Int64; number_of_paths::Int64 = 1000,
    seed::Union{Int64,Nothing} = nothing) -> Dict{String,NamedTuple}

Simulate synthetic paths of every asset of a portfolio, with the dependence between the assets that the dependence model gives. The way we draw the paths depends on the dependence model:

  • Copula: For each path, we draw uniform numbers from the copula and simulate one path of each asset from its hidden Markov model. Then we sort the growth rates of each asset and put them in the order of the ranks of its uniform numbers. The states and episodes stay as they were simulated
  • Single-index and hybrid: We draw the growth rates with sample_dependence. The states are 0 and the episodes are false, because these paths have no states. A hybrid portfolio has number_of_steps - 1 days, because sample_dependence drops the first day
  • Sector factor: We draw a seed for each path from seed, and call sample_dependence with that seed. The states of an asset are 0, and a day is an episode if the market, the sector, or the own draw of the asset was in a jump episode. The market gets its own states and episodes

Arguments

  • portfolio::MyPortfolioModel: The portfolio to simulate from
  • number_of_steps::Int64: The number of days in each path. Must be at least 1

Returns

  • Dict{String,NamedTuple}: One entry for each ticker, keyed by ticker. A sector factor portfolio also has an entry for the market. Each entry has three matrices with one row for each day and one column for each path.
    • growth_rates::Array{Float64,2}: The simulated growth rates
    • states::Array{Int64,2}: The state on each day
    • episodes::Array{Bool,2}: A flag that is true if the day is part of a jump episode

Optional Arguments

  • number_of_paths::Int64: The number of paths to simulate, at least 1. Default: 1000
  • seed::Union{Int64,Nothing}: The seed of the global random number generator. If nothing, the generator is not reseeded. A sector factor portfolio draws the seed of each path from seed. Default: nothing

JumpHMM.own_scale — Function
own_scale(σ²_own::Float64, σ²_u::Float64, σ²_drift::Float64; ticker::String = "") -> Float64

Compute the scale ψ of the own draw of one asset: ψ^2 = (σ²_own - σ²_drift) / σ²_u, with σ²_own and σ²_u from own_variances. The drift variance σ²_drift is the variance that a drifting β adds to the residual of the asset: drift_variance(β_halflife, β_scale) times the variance of the market growth rate. The drift variance is zero for a fixed β.

The single-index residual comes from a fit with a fixed β. That residual already holds the movement of the stock's actual β over time. We subtract σ²_drift, so that the synthetic drift does not add that variance a second time. Then the drift, sector, and own terms together carry the variance of the residual. The scale ψ also differs from 1, because the sector factor averages the residuals of its assets, asset i included. As a result, part of the leftover residual of asset i still moves with the sector factor. Independent draws lose that shared part, and ψ puts that variance back. We throw an ArgumentError (naming ticker) when the variance of the drift fills the whole own variance.

  • σ²_u::Float64: The variance of the leftover residual
