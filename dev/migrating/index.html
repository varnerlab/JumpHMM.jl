Migrating from 0.4

Version 0.5.0 renames the types, functions, and settings of version 0.4.1, and every model is now made with one build function. The old names are gone, with no aliases. With the same inputs and seeds, version 0.5.0 gives the same numbers as version 0.4.1, except for the three changes in Numbers that differ from 0.4.1.

General rules

Most changes follow a few rules:

  • Build, not fit: Every type is made with build(Type, data), where the NamedTuple data holds the inputs. The fit function and the positional constructors are gone.
  • Growth rates, not share prices: The single-asset build, tune, and validate take excess growth rates, which excess_growth_rates computes. The portfolio functions still take share prices.
  • No risk-free rate in the model: The single-asset model has no rf field. The portfolio stores rf and Δt and uses them when it computes growth rates.
  • Names: The setting N is now number_of_states, n_paths is number_of_paths, n_steps and n are number_of_steps, and dt is Δt. The word returns is now growth_rates, and jumps is now episodes.
  • Required settings: The keys number_of_states and ν have no default. Version 0.4.1 used N = 100 and ν = 5.0 when they were left out.
  • Exact types: Scalars are Float64 or Int64, and arrays are Array{Float64,1} or Array{Float64,2}. A function argument such as 126 where the function expects a Float64, or a view of an array, throws an error. Write 126.0 everywhere, including the keys of build.

The tables below write the names without the JumpHMM. prefix to save space. Write the prefix in your code.

Numbers that differ from 0.4.1

Three results differ from version 0.4.1 on purpose:

  • Hellinger distance: The function hellinger_distance counts every value of the two samples, where the 0.4.1 histogram left out the largest value.
  • Tail settings in tune: The function tune keeps the p_neg and N_tail of the input model when the call does not pass them, where version 0.4.1 reset them to 0.52 and 5.
  • Frank copula at θ = 0: A Frank copula with θ = 0.0 uses the formulas of the independence copula, where in version 0.4.1 the h-function returned NaN, its inverse returned a meaningless 3.8e-9 from bisection, and the log-density was -Inf, so the vine fit never selected such an edge.

Example

A 0.4.1 script and its 0.5.0 form:

# 0.4.1 -
model = JumpHMM.fit(JumpHMM.JumpHiddenMarkovModel, prices; N = 100, ν = 5.0);
tuned_model = JumpHMM.tune(model, prices; n_paths = 100, seed = 5660);
result = JumpHMM.simulate(tuned_model, 252; n_paths = 100, seed = 5660);
g_first_path = result.paths[1].observations;

# 0.5.0 -
g = JumpHMM.excess_growth_rates(prices; rf = 0.0, Δt = 1/252);
model = JumpHMM.build(JumpHMM.MyJumpHiddenMarkovModel, (growth_rates = g, number_of_states = 100, ν = 5.0));
tuned_model = JumpHMM.tune(model, g; number_of_paths = 100, seed = 5660);
paths = JumpHMM.simulate(tuned_model, 252; number_of_paths = 100, seed = 5660);
g_first_path = paths.growth_rates[:, 1];
